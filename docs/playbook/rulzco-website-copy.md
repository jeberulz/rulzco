## How I work: engagement model

Intro line
You have AI running in the backend. Your users still face a blank chat box. I build what goes between them.

### 1. Find the leverage
I find where AI helps your users and where it does not. We name the real problem, the user, and the outcome before any screens.

Tags: Problem framing / User need / Success metric

### 2. Design the interaction
I design how a person works with your AI. Flows, states, confidence signals, source display, and how a human steps in. The interface logic comes first.

Tags: Interaction design / AI behaviour / System logic

### 3. Build the frontend
I build the working interface on your live AI, not a static mockup. React, real API calls, and states that hold up when the model is slow or wrong.

Tags: Real build / Active states / Dev ready

### 4. Ship and refine
I ship, watch how people use it, and refine. Heatmaps, session data, and the changes that lift adoption.

Tags: Observation / Iteration / Launch

### Good fit
- Teams with AI working in the backend but a clunky or missing frontend
- Startups that bought AI access and cannot make it usable

### Not a good fit

- Fixed-scope briefs with no room to shape the problem
- Projects where AI is bolted on at the end
